# 全检大修记录（2026-11）

本次对仓库做了一次完整审查，分两步：**代码鲁棒性大修**、**易用性大修**。下面按模块列出改动、仍未处理的问题，以及后续建议。

> ⚠️ 本机没有 Create 6.0.10 与神秘时代 port.265 的编译期 jar，所以这批改动**未经编译和实机测试**。
> 已做的静态检查：全部 65 个 Java 文件语法解析通过，项目内部的方法/字段引用全部能对上，所有 JSON 资源可解析，中英文语言文件键完全一致。
> 合并前请先 `.\gradlew.bat build` 并进游戏验证一遍。

---

## 第一步：鲁棒性大修

### 大型奥法离心机

| 问题 | 后果 | 修复 |
|---|---|---|
| 外壳/端口/控制器的 `onRemove` 没调用 `super` | 拆解后旧方块实体残留在区块里，被还原的方块复用，端口失效 | 先读出记录的控制器坐标，再调用 `super.onRemove` |
| `requestDismantleNear` 取附近第一个控制器 | 两台离心机相邻时，拆的是邻居那台 | 优先用部件记录的控制器坐标；退回搜索时校验该部件确实属于候选结构 |
| `BlockPos.ZERO` 表示“未知控制器” | 建在 (0,0,0) 的离心机永远拆不掉 | 改为可空坐标，旧存档的 ZERO 自动视为未知 |
| 爆炸同时破坏多个部件 | 同一结构排队拆解多次 | 按维度 + 坐标去重；拆解时只覆盖“仍是离心机部件或已成空气”的位置 |
| 接收原初源质 | 原初源质无法分解，被直接吞掉 | 输入端拒收原初源质 |
| 批次结束只在 `gameTime % 20 == 0` 时同步 | 客户端一直显示“离心中” | 状态变化即标记同步 |
| 输入端六个方向都抽源质 | 端口上下方无关的源质罐也被抽空 | 只从朝外的一面抽取 |
| 每 tick 实体查询 + 冗余玩家循环 | 服务端开销 | 每 2 tick 扫描一次，去掉重复的玩家循环，跳过旁观者 |
| 法杖触发走两条路径 | 失败时提示与结构扫描执行两遍 | 触发返回 `Outcome`，事件监听在“结构匹配但失败”时也吞掉点击 |
| 渲染缓存不随资源重载清空 | F3+T 后贴图错位 | 注册客户端重载监听清缓存；`System.err` 改为日志 |
| 无用代码 | `LargeCentrifugeTransport`、`pushToOutputPipe` | 删除 |

### 炼狱锅炉

- `form()` 补 `try/finally`：成型中途抛异常不再让 `RESTORING` 永久为 true（否则之后所有拆解都失效）。
- `findBoiler` 只接受“4×4×5 范围确实包含查询位置”的锅炉，外壳方块实体记录所属锅炉，相邻两台锅炉不再互相拆、互相串流体/源质。
- 观察窗补上 `onRemove → 拆解` 钩子，掉落表清空：之前打碎观察窗会白得一个物品，结构还留着洞。
- 成型时记录被替换的原始方块，拆解原样还原：之前进阶炼金构材/进阶炼金炉会被降级，熔炉外壳会变成熔炉；流动岩浆不再算作岩浆源。
- 外壳 BE 在方块被替换时移除，不再残留。
- 交互事件监听改为 `receiveCanceled=false`，领地保护插件可以拦截成型。
- 热量只在服务端计算并及时同步；空闲时不再抽 Vis；负数提取不再“增加”源质，读档时钳位；`BlockPos.ZERO` 不再兼作“未成型”标记。
- `BoilerDataMixin` 在涡轮机数量变化时正确返回“已变化”；`SteamEngineBlockEntityMixin` 里影响全部蒸汽引擎、且实际从未生效的 `@Redirect` 已删除。
- 储罐里必须是水（或有管道供水）才算有水，岩浆不再能驱动锅炉。
- 只统计贴着真实锅炉方块的涡轮机，与涡轮机的供能判定一致。
- 世界渲染器每 20 tick 才重扫一次控制器列表（原来每帧遍历 25×25 区块的全部方块实体）。

### 奥法涡轮机 / 傀儡动力 / 红石发动机

- 涡轮机只认**水平相邻**的炼狱锅炉（原来 4 格内任何涡轮机都能白嫖满功率），需要水，取效率最高的那个储罐的数据。
- 涡轮机计算改为每 10 tick 缓存一次（原来每 tick 约 486 次方块实体查询 + 扫描整个储罐），客户端不再执行服务端逻辑，补上 `lastCapacityProvided`（读档后不再短暂超载）。
- 破坏涡轮机：原来 `playerWillDestroy` 先拆另一半，生存模式下很可能什么都不掉；现在每条破坏路径恰好掉 1 个物品，并带邻居更新与破坏粒子。
- 傀儡动力系统贴着已有传动轴放置时，输出轴方向正确对齐（原来会横着放，接不上）。红石发动机同理。
- 扳手翻转转向时，网络里每台设备**各自取反**，不再把齿轮啮合（本应反向）的设备强行设成同向导致爆转；网络里有其他类型动力源时拒绝翻转并提示。
- 红石发动机：非玩家放置（蓝图炮、`/setblock`、装置拆解）后也会读取当前红石信号；信号变化做了 10 tick 防抖，红石时钟不再触发 Create 的“闪烁”保护把方块弹掉。

### 高压动力发射器 / 弹药 / 配方 / 交易

- 13 个依赖神秘时代物品的弹药 JSON 加了 `neoforge:conditions`：物品 ID 变化时不再导致**所有世界无法加载**。
- `HighPressureAmmo` 改为懒加载并跳过未知 ID：两个 ID 缺失时 `Set.of` 抛重复元素异常，导致首次使用土豆加农炮时服务端崩溃。
- 只有本发射器射出的弹体才回收弹药：原来**普通土豆加农炮也 100% 回收**（刷物品）。
- ×2 初速只作用于本发射器开火，且读档重载的弹体不会再加速一次。
- 发射器带 Create“土豆回收”附魔时交给 Create 回收，本模组不再额外掉一份（原来会掉两份）。
- 爆炸/雷击记在射手名下，击杀正常计分；猪灵仇恨改用大脑记忆（原来那段代码从未生效）。
- 土豆加农炮背包里有一颗铁粒时不再“完全无法开火”：改为在可用弹药判定层过滤专属弹药，`HighPressureAmmoRestrictionEvents` 随之删除。
- `CenteredArcaneRecipe`：图案外格子必须为空（原来多余材料也能匹配并被吞掉）；按物品匹配，不再要求数据组件完全相同；补上研究完成检查。
- 奥术/注魔配方里缺失的物品 ID 会打日志并跳过该配方，而不是悄悄注册一个坏配方。
- 村民交易过滤空物品：原来缺物品时会生成空交易，打开交易界面可能直接把玩家踢下线。
- 涅里伊德之庇补上耐久（275，与神秘头盔一致；原来是无限耐久，与 README 不符）。

### 其它

- `create:non_movable` 标签 + `PushReaction.BLOCK` + `ContraptionMovementSetting.UNMOVABLE`：多方块部件不能被活塞/装置带走。
- 两个离心机端口方块状态 JSON 带 UTF-8 BOM，已去除。
- `gradle.properties` 带 BOM，导致第一行 `org.gradle.jvmargs=-Xmx2G` **从未生效**；注释乱码一并修复。
- `neoforge.mods.toml` 把 Create 版本限制为 `[6.0.0,6.1)`：本模组的 mixin 挂在 Create 6.0.x 内部类上，版本跳变时直接报“需要 Create 6.0.x”比启动崩溃更友好。
- 删除未注册的 `ArcaneTurbineResearchMixin`（研究已经是 `secondary`）和从未被调用的 `HighPressureAmmoActions`。
- 游戏总线监听从 `RegisterRenderers` 挪到客户端初始化，避免重复注册。

## 第二步：易用性大修

| **护目镜作为饰品** | 补上 Curios 实体槽位文件：原来没有其它模组提供头部饰品槽时，“饰品栏佩戴”根本用不了 |

| **研究图标** | 预加载全部研究图标，不再出现黑紫缺失纹理 |

## 仍未处理 / 需要你拍板的

1. **离心机拆解会丢弃内部最多 24 点源质**。可选：拆解时释放为咒波，或保留现状。需要神秘时代 port 的咒波 API。
2. **离心机控制器/外壳/端口没有物品形态**（README 已注明）。目前生存模式靠法杖成型获得，属设计选择。
3. **避雷针弹药只在雷暴天、目标头顶露天时生效**，研究页只写了“条件允许时”。建议把条件写进研究文本。
4. **`CenteredArcaneRecipe` 的研究检查也在客户端执行**，且 `player == null` 时不匹配。依赖神秘时代 port 的奥术工作台总是传入玩家、并把研究进度同步到客户端；若奥术工作台预览不显示产物，先查这里。
5. **首次启动请看日志**：配方里引用的神秘时代物品 ID（`thaumium_helm`、`air_crystal_cluster`、`air_shard`、`fire_shard`、`bellows`、`alchemical_construct`、`copper_diving_helmet` 等）若有任何一个打出“找不到配方物品”，对应配方会被跳过。
6. **神秘时代版本范围** `[0.2.2.95,)` 没有上限，同样存在 mixin 失配风险，可按需收紧。

## 后续建议

- **配置文件**：傀儡转速/应力、红石发动机上限、离心机容量与转速区间、旋转伤害开关目前全部硬编码。Create 的应力登记接受 `Supplier`，可以直接读 `ModConfigSpec`，整合包作者会很需要。
- **JEI / 思索（Ponder）**：两个多方块结构只能靠研究书看搭建图，给 Ponder 做结构动画、给 JEI 做奥术配方分类，上手成本会低很多。
- **自动化测试**：`tools/rcon_test.py` 已有 RCON 冒烟测试雏形，可以扩展成“成型 → 破坏 → 检查还原”的回归脚本，覆盖本次修过的拆解逻辑。
